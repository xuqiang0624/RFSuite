# 迭代路线与验收标准

本文件记录 RFSuite 的模块迭代与验收口径。每次提交对应一个可编译、可回滚的节点，
提交前需满足「编译通过 + 相关用例通过 + 无编译产物入库」三项要求。

## 阶段 A：工程地基

- 建立 CMake + Qt6 工程骨架，最小主窗口可运行；
- 明确 `core / widgets / app` 三层目录与头文件包含规范；
- 统一命名、文件头注释、`.clang-format`；
- 验收：全新目录 `cmake -S . -B build && cmake --build build` 一次通过。

## 阶段 B：并发采集链路

- worker-object + `moveToThread` 实现采集线程，禁止继承 `QThread` 重写 `run()`；
- 线程安全环形缓冲，`QMutex` / `QWaitCondition` 保护，丢帧可计数、可核对守恒；
- 跨线程信号槽显式 `Qt::QueuedConnection`，UI 侧限帧刷新（约 30 fps）；
- 验收：`--selftest=6` 10 万帧压测，生产数 = 消费数 + 丢弃数；线程退出无泄漏。

## 阶段 C：自绘控件库

- 继承 `QWidget` 重写 `paintEvent`，实现频谱轨迹、瀑布图、门限仪表三个控件；
- 坐标映射（dBm ↔ 像素、频率 ↔ 像素）、网格与刻度、双缓冲避免闪烁；
- 控件与业务解耦，可独立编译为静态库，QSS 支持主题切换；
- 验收：`--lab=10/11/12` 单控件窗口可运行，持续刷新无崩溃、内存不持续增长。

## 阶段 D：通信与存储

- TCP 自定义帧协议（长度前缀 + 校验），处理粘包、半包、超长包、断线重连；
- SQLite 批量事务写入、按时间区间查询与回放；
- 门限报警与事件记录；
- 验收：`--selftest=16` 四类异常用例全 PASS；连续运行 10 分钟数据库不锁死。

## 阶段 E：架构工程化

- `buildChain()` 单一接线点串起「采集 → 显示 → 存储 → 上报」全链路；
- 抽接口、补观察者/策略模式，配置外置、日志分级；
- 补 CMake 安装规则与打包脚本；
- 验收：模块可单独替换而不改 UI 代码；`git status` 干净，仓库体积 < 5 MB。

## 阶段 F：文档与交付

- 补齐架构设计、通信协议、性能记录、联调记录、代码规范；
- 记录实测数据（帧率、吞吐、内存），不写未经测量的数字；
- 打 `v1.0.0`，导出可运行演示包，按 README 在全新目录复现编译；
- 验收：文档齐全、`git status` 干净、仓库体积 < 5 MB，
  且 README 的编译步骤在干净环境一次跑通。

## 提交与 tag 约定

```
feat:      新增采集线程与线程安全环形缓冲
feat:      QPainter 自绘频谱控件与坐标映射
fix:       修复跨线程信号未排队导致槽不执行
refactor:  抽出静态控件库，解耦 UI 与业务逻辑
docs:      补齐架构设计与设备通信协议
```

阶段结束打 `stage-A … stage-F`，最终 `git tag -a v1.0.0 -m "RFSuite 交付版本"`。
提交粒度以「单个可编译、可回滚的变更」为准。
